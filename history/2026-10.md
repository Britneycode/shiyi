### v1 vs v2

HanaAgent 有两种扩展格式。v1 插件（manifestVersion: 1）已被官方冻结，不再加新功能。v2 app（manifestVersion: 2）是活跃开发线。茶话会/拾光记/表情包**全是 v2 app**。

### 已确认的 v2 API 签名

#### 入口

```js
// 拾光记模式：named export + default export
export const name = 'xueban';
export async function apply(ctx) { /* ... */ }
export default apply;

// 表情包模式：defineApp 包装
import { defineApp } from "./sdk/app-contract/server-client.js";
export default defineApp(async (sdk) => { /* ... */ });
```

**关键约束**：`apply()` 里**不能**调用权限受保护的 API（`ctx.bus.request`、`ctx.resources.*`、`ctx.models.*`）。只能做：注册 hook、注册路由、注册服务、设定时器。真正的 API 调用放在 hook 回调、路由回调、定时器回调里。（来源：茶话会 README 明确规则 + 拾光记 index.js 实际结构）

#### 存储

- `ctx.dataDir` — 插件私有目录（`HANA_HOME/app-data/<id>/`），卸载后保留。可直接 `fs.writeFileSync`。
- `ctx.resources.read/write` — 用户可见资源目录，需要 `app/resources.read` / `app/resources.write` capability。

### 表情包的关键踩坑记录

1. **App 沙箱限制**：代码跑在 Node 权限沙箱子进程，能碰的目录只有安装目录、自己的 app-data、宿主语言包。读 `agents/` 目录会被 `ERR_ACCESS_DENIED` 拒绝。必须用 `ctx.resources` 或 `ctx.bus.request` 走正门。
2. **模块加载顺序**：`lib/shared.js` 在模块加载时定死 DATA_DIR，必须在 `apply()` 里设好 `process.env.BQB_DATA_DIR` 后再动态 `import`，不能用顶部静态 `import`。
3. **宿主不渲染 assistant 消息里的图片块**——不要试图往 assistant 消息里塞图片。

### 四个实现级事实结论（2026-10-25 二轮源码查证）

| 问题 | 结论 | 证据 |
|---|---|---|
| 沙箱能否用 node:sqlite | **不能赌**——app 子进程启动 flag 由宿主决定，sqlite 可能需额外 flag。三个参考 app 全用 JSON+原子写，无一用 sqlite | 茶话会 store.js / 表情包 atomic-store 全是 fs.writeFileSync；biaoqingbao index.js 顶部通道选型注释（子进程受 Permission Model 约束） |
| inputStatus 按钮是否需要 expose-to-model | **需要**——按钮机制就是宿主调用 manifest `toolName` 指向的工具，工具必须对模型可见 | 表情包 sticker-input-panel.js:115 `sdk.tools.register({name:'stickers.open_compose'})` + 其 manifest 声明该 capability |
| 错过的提醒会补发吗 | **会**——TaskRegistry 持久化计划，重启标 recovering 补跑；runScheduled 只跳过早（nextRunAt>now+20），晚到照发。**例外**：中断时状态为 sending 的通知标 unknown 不重发（防重复） | 拾光记 todo-reminder-scheduler.js:642-652 / restoreAppSchedules:249-271 |
